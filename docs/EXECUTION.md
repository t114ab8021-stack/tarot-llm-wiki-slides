# 一次實際執行紀錄

## 討論與來源取得

2026-11-10，使用者確認「沿用」塔羅入門主題後才生成本專案。實際開啟六個候選教學來源：五篇取得正文，一篇 MIT 網頁只回傳載入提示，因此不 ingest。圖像來源另外查核，不灌入五篇文章數量。

正文取得工具為 web reader。LLM 將讀到的內容整理成來源筆記與主張；`ingest.mjs` 驗證筆記、輸出 Markdown 並計算雜湊。它不會冒稱重新爬取來源，也不是五個 URL 存進檔案就算 ingest。

## 真實事件與處理

| 節點 | 實際事件 | 處理與證據 |
| --- | --- | --- |
| N2／N3 | MIT 候選頁只有 JavaScript／Loading 提示 | R01 rejected；來源閘門前移；改用 The Strong 的可讀正文 |
| N4 | 十八世紀用途出現、十九世紀普及的描述容易被濃縮錯 | C05 保留兩個時間層次 |
| N4 | 「第一套完整小牌插圖」及撲克牌系譜缺乏本次交叉查證 | 兩項主張不收入可用 claim，保留來源限制 |
| N6 素材準備 | Windows PowerShell 將傳給 Node stdin 的中文目錄名轉為問號，造成 ENOENT | 改讀前份作業內已有的 ASCII 路徑來源清單；三張圖片 SHA-256 驗證成功 |
| N6 素材準備 | 補查圖像時誤用 Pentacles08.jpg，工具無法開啟 | 回讀既有來源清單，正確檔名為 Pents08.jpg；三張圖片來源頁均已核對公有領域標示 |
| N7 | 第一輪瀏覽器測試在第 1 頁失敗，桌機捲動高度 775，容器 769 | 封面 min-height 與留白重複計算；改為 flex 可用空間分配。失敗原報告在 runs/browser-first-failure.json |
| N7 | 修正後重跑 | 14 頁 × 4 種尺寸通過；兩題測驗、筆記儲存、倒數、來源筆記、搜尋及列印可見性通過 |

工程素材路徑錯誤是實際執行問題，但不是來源文章的內容錯誤。內容核對的三個風險旗標也不能當成三次系統失敗。

## 本次檢查

- 5 篇來源筆記、5 個交叉連結知識頁、12 個主張、14 張投影片。
- 4 次關鍵詞查詢：歷史／年代、結構／花色／宮廷、RWS／繪者、觀察／提問／練習。
- 每個投影片 claim 都屬於其標示的 Wiki 頁；史實／方法的來源全部為 accepted。
- 四種瀏覽器視窗：1440×900、1366×768、390×844、320×568。
- 桌機每頁可完整顯示；手機可在投影片內容區自然捲動，不橫向溢出。
- 已視覺檢視 14 頁縮圖及手機筆記頁。
- 無公開儲存全文文章；只提供短摘句、自行整理摘要及原始連結。

## 限制

這是一次 LLM 輔助執行，不是長期統計。不同失敗事件計數：N6 素材準備 2 項最多，N2／N3 正文讀取 1 項，N7 桌機版面 1 項。內容風險集中在 N4 共 3 項，但風險不等於程式故障，也無法由一次執行推論長期失敗率。

瀏覽器是自動化 Chromium／Edge，不是手機實機。列印只測試全部 14 張內容可見，沒有實體印表機驗證。程式檢查能驗證引用 ID 與檔案存在，不能取代史實閱讀核對。
